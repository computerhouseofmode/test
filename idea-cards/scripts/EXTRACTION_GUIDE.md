# カード候補 抽出ガイド（第3段階・全記事共通）

発想カードは、ランダムに3枚表示されたカードを見て、過去の考えを思い出したり新しい発想を得たりするための個人用ツール（筆者：note「もーふ」）。学習用ではない。
良いカード＝「これを見たら、あの記事を読み返したくなる」「別のカードと掛け合わせると何か思いつきそう」なもの。

## 入力と出力
- 入力：`articles/{ファイル名}.md`（冒頭に title / url / published / chars）。`（画像キャプション）` は筆者が画像に付けた説明文で、本文の一部として扱ってよい。
- 出力：`extracted/{記事ファイル名}.json`（例：`articles/2025-05-06_nxxxx.md` → `extracted/2025-05-06_nxxxx.md.json`）
- **既に JSON がある記事はスキップする。**
- 件数：`selection.json` の `alloc`（配分件数）を目標にする。記事に中身が足りない場合は下回ってよい（水増ししない）。ただし区分の下限（〜2000字は5件、2001〜5000字は8件）を大きく割るなら理由があるはず。

## JSON形式（UTF-8、ensure_ascii=False）
```json
{
  "title": "記事タイトル", "url": "記事URL", "published": "YYYY-MM-DD",
  "cards": [
    {"word": "...", "type": "固有名詞|概念|文", "back": "...", "back_kind": "文脈|辞書"}
  ]
}
```
title / url / published は記事ファイル冒頭の値をそのまま使う。カードは記事内の登場順に並べる。

## 種別
- **固有名詞**：人名、作品名、地名、機材名、展覧会名、店名など。表記は記事中の表記に従う（明らかな誤字は正してよい）。
- **概念**：記事の中で意味を持って使われている語や考え方。筆者独自の言い回し・造語・キーワードも含む（例：「揺れる気持ちを楽しむ」ではなく、それを凝縮した名詞句なら可）。概念は名詞または短い名詞句にする。
- **文**：記事の主張や気づきを、**20〜40字**の言い切り（常体）の一文に凝縮したもの。原文の書き写しではなく、要点を自分の言葉で整える。単独で読んで意味が通ること（指示語で記事に依存しない）。

1記事の中で少なくとも2種類以上を含める。全体でいずれの種別も20%以上になるよう、目安として各記事で「固有名詞：概念：文 ≒ 4：3：3」程度を意識する（固有名詞が少ない記事は概念・文で補い、逆も同様。無理に作らない）。

## 抽出しないもの
- 一般的すぎて何も喚起しない語（「仕事」「時間」「写真」単独など）。ただし記事中で独自の意味を与えられている場合は概念として採ってよい。
- 記事の文脈がなければ意味をなさない指示語を含む文（「それが大事だ」など）。
- 同一記事内で実質的に重複するもの（同じ人物の別表記、同じ主張の言い換えなど）。
- 家族・友人・同僚など、筆者以外の私的な人物を特定できる情報（名前・あだ名・勤務先など）。家族のエピソードを裏面に書く場合も「家族」程度の一般化にとどめる。公人（作家・音楽家・芸人・写真家など）は可。
- 筆者自身の個人情報（住所・勤務先・本名など）が記事にあっても採らない。

## 裏面テキスト（back）
- **80〜150字**、常体（である調）。
- その語が記事の中でどのような論旨・場面で出てきたかを要約する。筆者がそれについてどう考えたか、どういう結論（あるいは結論の保留）に至ったかに触れる。主語は「筆者」とする。
- 「文」カードの裏面は、その気づきに至った場面や根拠を要約する（表の文の言い換えにしない）。
- 記事での言及が浅く文脈を要約できない場合に限り、一般的な辞書的説明を書き、`back_kind` を「辞書」とする。それ以外は「文脈」。
- 記事に書かれていない事実を補わない。辞書的説明でも、確実に知っていることだけを書き、不確かな事実（年代・所属・受賞歴など）は書かない。自信がなければ辞書カードにせず、そのカード自体を採らない。

## 最後に
書き終えたら `python3 scripts/check_extracted.py {JSONファイル…}` を実行し、警告が出たら直す。
